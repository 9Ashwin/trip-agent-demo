## 一、先破除一个误解

很多人第一反应是：「我把 HTML 改成网页格式，它不就能自己联网了吗？」

**不能。** 这跟文件格式无关，是浏览器的硬性限制：

| 障碍 | 说明 |
|---|---|
| **CORS 跨域** | 浏览器禁止 JS 直接请求携程、12306 等站点 |
| **没有 AI 工具** | 网页里的 JS 没法调用「搜索」这种服务端能力 |
| **API Key 会泄露** | 前端代码用户全都能看到，Key 放前端等于公开 |
| **需要服务端计算** | 搜索 → 解析 → 再喂给模型 → 拼装结果，这串活需要程序在服务器上跑 |

**结论：联网能力必须放在「页面之外」那一层，也就是后端。**

## 二、正确的架构长什么样

```
你的浏览器                     你的后端服务器                    外部服务
┌──────────┐   POST 需求   ┌─────────────────┐   工具调用   ┌──────────────┐
│ 前端页面  │ ───────────→ │  Flask 后端     │ ──────────→ │ 搜索 API      │
│ (HTML)   │               │                 │              │ (Tavily/博查) │
│          │ ←─────────── │  ① 保管 API Key │              └──────────────┘
│  显示结果 │   SSE 实时推  │  ② 跑 Agent 循环 │   对话请求   ┌──────────────┐
└──────────┘               │  ③ 真的去联网搜  │ ──────────→ │ 大模型 API    │
                           └─────────────────┘              │ (DeepSeek)   │
                                                            └──────────────┘
```

**分工一句话：前端只负责「显示」，后端才负责「干活」。**

## 三、最核心的机制：工具调用（Function Calling）

整件事的关键，就在 `agent.py` 里这段循环：

```
1. 后端把 web_search 这个工具「告诉」大模型
      ↓
2. 大模型判断：「我需要知道广州到昆明的机票价」
   → 返回一个 tool_call：{ name: "web_search", query: "广州 昆明 机票 9月30日" }
      ↓
3. 后端收到指令，真的去调搜索 API，拿到网页摘要
      ↓
4. 把搜索结果塞回对话历史，再问大模型一次
      ↓
5. 重复 2-4，直到大模型说「信息够了」→ 输出最终方案
```

**重点：大模型自己不能上网。** 是它「指挥」后端去搜的。
豆包智能体、扣子 Bot、以及各种「联网 AI」底层都是这个套路。

代码见：
- `agent.py` → 第 47-141 行，工具定义 + Agent 循环
- `search_tool.py` → 真正发 HTTP 请求去搜索的那 30 行
- `app.py` → Flask 接口，把每一步用 SSE 实时推给前端

## 四、接上真实数据（4 步）

### 第 1 步：拿一个大模型 Key

**想零成本？直接用永久免费的 GLM-4-Flash：**

| 平台 | 免费模型 | 额度 | 说明 |
|---|---|---|---|
| **智谱 AI** ⭐ | `glm-4-flash` | **永久免费** | 中文最强，国内直连，首选 |
| 硅基流动 | Qwen2.5-7B 等 | 9B 以下永久免费 + 新人 2000 万 Token | 一个 Key 通吃几十家模型 |
| 火山引擎（豆包） | Doubao-Lite | 每日 200 万 Token 自动刷新 | 需先在控制台手动开通 |
| 百度千帆 | `ernie-speed-128k` | 永久免费 | 需实名认证 |
| 腾讯混元 | `hunyuan-lite` | 永久免费 | 生态内方便 |

**智谱的填法**（复制进 `.env`）：

```
LLM_API_KEY=你的智谱key
LLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4/
LLM_MODEL=glm-4-flash
```

> 去 https://open.bigmodel.cn 注册 → 「API Keys」生成。

**想效果更好、愿意花点小钱？用 DeepSeek**（中文强，¥0.7/百万 token，最低一档）：

```
LLM_API_KEY=sk-你的key
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
```

**⚠️ 选模型时必须确认一件事：支持 function calling（工具调用）。**
本项目靠它让模型「指挥后端去搜索」，不支持的话模型永远不会调用 `web_search`。
GLM-4-Flash、DeepSeek、GPT-4o-mini、Qwen 系列都支持；一些小模型或老模型可能不支持。

> 其余平台只要兼容 OpenAI 接口格式，改 `LLM_BASE_URL` 和 `LLM_MODEL` 就行。

### 第 2 步：拿一个搜索 Key（二选一）

| 提供方 | 特点 | 地址 |
|---|---|---|
| **Tavily** | 专为 AI Agent 设计，免费 1000 次/月，国际线路 | https://tavily.com |
| **博查** | 国内可直连，按次计费，国内网络首选 | https://open.bochaai.com |

```
SEARCH_PROVIDER=tavily
TAVILY_API_KEY=tvly-你的key
```

> **关于 DuckDuckGo（不要指望它）**
> 代码里有 DDG 作为免 Key 兜底，但实测有双重问题：
> 1. **网络不通** —— `duckduckgo.com` 与 `api.duckduckgo.com` 在国内无法访问，实测连接直接失败
> 2. **接口性质不对** —— 用的是 Instant Answer API，它是「百科摘要」接口（返回词条 Abstract
>    和 RelatedTopics），**不是搜索引擎**。对「广州 昆明 机票 9月30日 价格」这类查询
>    通常返回空结果
>
> 所以它只能算「聊胜于无」，要真实效果请配 Tavily 或博查。

```bash
./run.sh
```

启动横幅会从「演示模式」变成「真实模式」，页面上方的徽章也会变绿。

## 七、部署上线

### 方式一：WorkBuddy 的「发布为应用」（本项目已用这个方式发布）

在 WorkBuddy 里对它说一句「发布这个项目」即可，不用自己买服务器、配域名。
发布前确认两件事：

1. 服务绑定 `0.0.0.0`（本项目 `app.py` 已改好）——绑定 `127.0.0.1` 的话线上访问不到
2. 读取 `PORT` 环境变量（已改好）——部署平台会注入这个变量

### 方式二：自己部署

- **后端**：Railway / Render / 腾讯云 Serverless（都支持 Python + 环境变量）
- **前端**：如果只用静态版，可以单独丢到 Vercel / Netlify
- **环境变量**：Key 配在平台的环境变量面板里，**不要**写进代码或提交到 Git

### ⚠️ 线上版本要用真实搜索，必须配 Key

线上沙箱里没有你的 `.env`。想让**在线版**也能真实联网搜索：

1. 在本地把 `LLM_API_KEY`、`TAVILY_API_KEY` 填进 `.env`
2. 重新发布一次（覆盖线上版本）

> **安全提醒（重要）**
> 线上版本一旦配了 Key，就等于把「调用额度」公开了 —— 任何拿到分享链接的人
> 都能消耗你的额度。给朋友看 Demo 用**演示模式**就够了。
> 如果你确实要上线带 Key 的版本，本项目已内置 **按 IP 限流**兜底：
>
> ```
> RATE_LIMIT_PER_HOUR=20     # 每个 IP 每小时最多 20 次，0 = 关闭
> ```
>
> 超过会返回 `429`，前端会提示「请求太频繁了」。这个配额对朋友试用绰绰有余，
> 但能挡住恶意刷量。注意限流是**进程内存**实现，多实例部署需换成 Redis。
>
> 发布前记得确认 `.env` 没有被一起上传（本项目 `.gitignore` 已排除，但仍建议
> 手动核对上传清单）。

## 八、常见坑

| 现象 | 原因 | 解决 |
|---|---|---|
| POST 请求返回 **403** | macOS 的 5000 端口被 AirPlay 接收器占用 | 用 5050 端口（本项目已默认） |
| 页面上方一直是「后端未连接」 | 后端没启动 | 先跑 `./run.sh` |
| 一直返回「演示数据」 | 没配 `LLM_API_KEY` | 填 `.env` 后重启 |
| 搜索结果很少 | 用了 DuckDuckGo（国内不通 / 是百科接口） | 配 Tavily 或博查，见第四节 |
| 模型不调用搜索 | 模型不支持 function calling | 换 deepseek-chat / gpt-4o-mini 等 |
| 页面提示「请求太频繁」**429** | 触发了按 IP 限流 | 等一小时，或调大 `RATE_LIMIT_PER_HOUR` |

### Q：能不能直接复用 WorkBuddy 的模型能力，不自己的 API Key？

**不能。** 原因：

1. WorkBuddy 是 **客户端 AI 办公产品**，不是模型 API 服务商 —— 官方文档里只列了文档生成、
   数据分析、PPT 生成等能力模块，**没有对外的开放 API / API Key**。
2. 它按**积分套餐**计费（体验版每月 500 积分、标准版 2000 积分……），
   没有提供「按调用量付费给第三方网站用」的接口形态。
3. 架构上它处在**终端**位置：你在 WorkBuddy 里对话，它调用模型、操作你本地文件。
   它不是一个能被别的网站反向调用的中间层。

**那「复用 WorkBuddy 能力」的正确姿势是什么？**

不是在运行时调它，而是在**开发时**用它：

| 你想做的事 | 正确的做法 |
|---|---|
| 生成/修改这个项目的代码 | 直接对 WorkBuddy 说需求，它写代码、跑测试、发布上线 |
| 每天自动跑一次旅行规划 | 用 WorkBuddy 的**定时任务**能力，不用部署网站 |
| 连自己的数据源（邮箱、表格、数据库） | 用 WorkBuddy 的 **MCP 连接器** |
| 做一个给别人用的联网网站 | ← 就是本项目，**必须有自己的模型 Key** |

**一句话：WorkBuddy 是帮你「造工具」的，不是给别人「当零件」的。**

> 顺带提醒：本项目已发布的在线版本用的是**演示模式**（假数据）。
> 想让在线版真实联网，需要在本地 `.env` 填 Key 后重新发布 ——
> 但那等于把调用额度公开了，只给朋友看 Demo 的话没必要。

## 九、下一步可以做什么

- **加流式输出**：让方案文字也一个字一个字蹦出来（对 `LLM` 请求开 `stream=True`）
- **多轮对话**：把 `messages` 存在浏览器 localStorage，支持追问「换一家酒店」
- **导出 PDF**：前端加 `window.print()` + 打印样式
- **部署上线**：后端丢到 Railway / 腾讯云 Serverless，前端丢到 Vercel
- **换成别的 Agent**：改 `agent.py` 里的 `SYSTEM_PROMPT` 和工具定义，就是另一个领域的 Agent 了

---

**一句话总结：网页负责好看，后端负责干活，大模型负责指挥。** 三者分工搞清楚了，这类「能联网的 AI 网站」就没什么神秘的了。
